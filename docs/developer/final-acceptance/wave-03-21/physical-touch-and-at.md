# Physical reorder operator protocol (unrun)

Required operator: a person with a named physical touchscreen device and remote browser inspection; separately name the screen reader and version. Device emulation, Playwright touchscreen taps, event.isTrusted and maxTouchPoints alone cannot prove physical origin. Record the actual device/model, OS/browser/AT versions, input method, locale, density, fixture build hash and source manifest. Keep AT-off physical gesture results separate from AT-on touch exploration or drag commands. Never describe a touch scroll or selected text as a successful drag.

Use an isolated coordinator-owned fixture host containing the recorded current build. Preserve the user's server on port 3000. No rebuild is needed for this protocol if existing fixture hashes match; native input must be executed on the device, not from an automation mouse.

Fixtures:

- `/fixtures/?id=data-display-datagriddraghandle--strict-mode-reorder&globals=a11y.manual:!true`: five rows, exact host request count, optimistic save/rollback and remount.
- `/fixtures/?id=data-appdatagrid-pointer-invalidation--host-replacement-and-cross-grid&globals=a11y.manual:!true`: two grids with colliding IDs and an armed host replacement strip. Its host trigger is native dragenter; if this device's touch implementation uses a different interaction and never enters that strip, report this case as unsupported by this fixture, not passed. Coordinator must then add a physical-input-compatible trigger with a separate trace before acceptance.

Paste `physical-input-recorder.js` in the physical device browser console. It observes native events, focus, order, request statuses and drag affordances without triggering actions or changing state. Mark each attempt with `sguiReorderCapture.mark('case/start')`, then `mark('case/end')`; save `JSON.stringify(sguiReorderCapture.export())` in a named JSON artifact and call `.stop()` afterward. Save a device recording and screen-reader transcript separately. The recorder's timestamps and DOM snapshots supplement that evidence; they cannot infer spoken output or physical origin.

Execute and record each case (fresh navigation when initial order is required):

1. **Touch before/after:** long-press the Course 2 handle, move to a nonadjacent before/after drop position, release. Verify actual drag start, correct target and exactly one request, the expected five-row order, saving then saved status, source focus, and no leftover indicators. Before Course 1 yields 2,1,3,4,5; after Course 4 yields 1,3,4,2,5. Record actual gesture and duration. If the platform presents a drag action rather than long-press, record that route separately; do not silently substitute Move.
2. **Cancel:** start an actual touch drag, move outside the grid and release. Also use the platform's actual cancel gesture/command where supported. Require zero host requests, unchanged rows and selection, clean indicators, and source focus. Mark unsupported cancellation mechanisms explicitly; Escape via an attached keyboard is a separate keyboard result.
3. **Rollback:** activate Reject next move, then complete a physical touch drag after Course 4. Require one request, optimistic order, pending disablement, failure status, original order restored, source focus and no duplicate request. Repeat a fresh successful interaction to prove cleanup.
4. **Invalidation and sibling isolation:** in the second fixture arm dataset replacement, start physical drag of Source Course 2, enter the strip and verify Revision 1 before releasing at Source Course 4. Require zero requests for both grids, unchanged orders, source focus and clean indicators. Repeat for identity replacement. Separately drag Source Course 2 to Other Course 4 with colliding IDs; require zero requests in both grids and unchanged sibling selection/order. If native touch does not produce the fixture's host trigger, keep invalidation unrun and retain desktop pointer evidence.
5. **Non-drag touch:** tap Move down once in the first fixture, require exactly one request and host order. Reject the next Move, require one additional request and rollback. This is an alternative action, separate from drag success.
6. **Spoken AT:** with the named AT active, navigate to the handle, start drag using the supported AT command, navigate a named before/after target, cancel, then perform a valid move. Capture the actual spoken source name, target position, cancellation, and move request. Require no persistence claim before host save; capture saved/failure feedback. Record AT focus after each operation and unchanged sibling state. A live-region string found in DOM is not proof of speech.

Sorting/filter/page guards and their restoration belong to the focused unit proposal plus retained pointer policy evidence; do not change the processing model for a device test. Before marking acceptance, coordinator must reconcile exact input hashes and runtime results. If long-press dragging fails, attach the event/video trace and produce a concrete supported-platform fix; never close these leaves using this protocol alone.
