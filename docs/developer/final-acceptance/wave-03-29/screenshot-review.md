# Deliberate screenshot review protocol — A-X-15 / A-B-07

This proposed procedure is ready for coordinator adoption; it is not a completed visual review or an automatic baseline updater. Existing HB review statements retain their original attribution. Twenty-eight recorded HB artifact roots remain absent. The available calendar PNG inventory has pending review and unverified family attribution.

1. Freeze the source inputs, built package and fixture output. Store path/SHA-256 manifests and run receipt together. Resolve the fixture in `/fixtures/index.json`. Record engine version, OS, viewport, theme, density and intended state. Preserve original failure captures and corrected captures as separate artifacts.
2. Retrieve original image and replacement locally. Hash both. Open each at original dimensions, then examine their side-by-side or diff presentation. Review text clipping/wrapping, control boundaries, focus outlines, selected/disabled/error states, alignment, scrollbars, portal surface/theme and unexpected page shifts. A pixel match proves file equality only.
3. Record one explicit disposition per image (`accepted`, `rejected`, `deferred`), actual reviewer/date, specific observed differences and why intended. New baselines require an explicit reason. Rejection/deferral requires a bounded follow-up. Do not run snapshot-update commands merely to silence failure. Keep original hashes even after intended replacement.
4. Use `review-receipt.template.json`; image and manifest paths resolve from repository root. Fill actual observations; do not use the synthetic unit fixture as a receipt. Run `node docs/developer/final-acceptance/wave-03-29/review-receipt.mjs <receipt.json>`. This verifies structure and bytes only. Coordinator still reviews evidence and integrates the procedure.
5. Required B-07 set: controls, editor, navigation, modal and grid, each light/dark × compact/comfortable. First recover accepted exact artifacts; capture only missing combinations on an immutable host. A fixture decorator may hardcode a scope, so inspect rendered scope and record effective settings rather than assuming the URL override applies. Capture both overlay and trigger context for modals. Include actual interaction receipt with each family (activation, editing, route request, open/dismiss/return, selection/sort respectively). Screenshots alone do not certify these flows.

Never equate Playwright WebKit with a real Safari/iOS device, emulated touchscreen with physical touch, text-size CSS with browser zoom, or DOM/axe output with spoken assistive technology. Keep those successors separate.
