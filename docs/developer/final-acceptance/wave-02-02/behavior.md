## GRID-R1 — accepted host field collides with reorder utility ID

Source-confirmed defect, scoped local identifier; coordinator assigns any shared BUG ID. Both `createOwnedGridColumns([{field:'__reorder'}])` and `processOwnedGridRows` accept this field. `ownedGridInteraction.tsx:386` supplies a utility Column with exactly that ID when rowDrag exists, then supplies each accepted host field as another Column ID. Thus the same ID can reach the collection twice. No rendered exception or browser behavior is claimed from helper execution.

Reproduce without shared writes: `node docs/developer/final-acceptance/wave-02-02/capture.cjs`. `checks.txt` records that `__selection`/`__drag` are rejected as controls, whereas `__reorder` is built and processed successfully. Current helper executions used Node v26.5.0 and in-memory TypeScript transpilation; they are separate from retained Node 24 validation and do not establish the supported-version matrix.

Required successor: reserve actual utility IDs consistently in presentation and processing validators, preferably one shared authoritative list. Add a focused failing-first validator assertion for `__reorder` and a public rowDrag composition case confirming rejection occurs before duplicate collection keys render. Preserve existing reserved names and ordinary host field behavior; run only affected model/column/public-grid units and typecheck when implemented. The report-only assignment cannot apply this source fix. A-M-16 and A-G-02 remain partial.
