The common IDREF assertion checks currently mounted `aria-labelledby`, `aria-describedby`, `aria-controls`, and `aria-activedescendant` targets in the owner document, including portals. It does not prove screen-reader speech, label quality in every application, or an all-library heading/landmark audit. A failing reference assertion must be diagnosed against that exact state rather than suppressed globally.

## Keys with different contracts

Select and Menu are noneditable collections: Home/End move collection focus and printable characters perform typeahead. ComboBox keeps DOM focus in its editable input; Home/End have native cursor semantics while arrows track the active option and Enter commits its ID. Space inserts text in ComboBox; it activates Menu commands and opens the Select trigger. Do not add Menu-style Space selection or typeahead to the editable input.

Popover is arbitrary form/help content inside a named dialog: Tab/Shift+Tab stay in its focus scope, text editing belongs to native fields, Escape dismisses through the outer surface. Tooltip is supplementary plain text, not an interactive popup; it does not receive a separate Tab stop. The new Popover case establishes entry/exit/content focus, not a complete containment matrix. Dialog containment already has separate tests; retain their exact receipts rather than relabel this case.

## Unresolved required hierarchy

`hierarchical-menu-scope.md` explicitly approves sliding drilldown, excludes flyouts, and leaves HM-F-01–04 open. No current generic Menu child field or standalone panel implements that contract. These tests deliberately exercise only the shipped flat command model. A-U-07 cannot close through flat-menu evidence. Coordinator should assign HM-F-01–04 implementation as its own leaf-sized patch series, including navigation-versus-command composition, public playground/exports, forward/Back focus and the existing SideNavigation compatibility constraints. This report does not invent or certify that missing component.
