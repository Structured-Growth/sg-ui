# Remaining trust decisions and bounded implementation

The proposed patch enforces the already declared image field types at runtime. It does not select a new URL allowlist, purge saved sources, strip CSS or certify an entire document. `ImagePayload` is a TypeScript interface; imported JSON and asynchronous host output can violate it. Before this patch, an object asset ID entered saved output and a non-string description reached rendering. The added factory guard rejects those values; the section checks host output before dispatch and reports a retryable translated error. Missing/null optional values retain the existing normalization. Finite dimensions are checked for representability, with no new positive/minimum/maximum policy. Valid markup-shaped descriptions are escaped by React and preserved in JSON.

The current image `version` is not migrated or newly rejected. Whole-document structural validation, atomic rejection and recovery remain unimplemented. The section supplies `onError: () => {}` to Lexical; therefore a factory TypeError is not evidence that the user sees a meaningful whole-document rejection. A host must preserve the original and validate it before passing untrusted documents. Do not treat partial parsing or a subsequent change callback as permission to overwrite that original. Coordinate any document-load policy with the E-02 owner.

## Bounded coordinator browser checks

After integrating the patch and rebuilding the public library/private host, run the existing `editor-image-sources.spec.ts` and `editor-upload-lifecycle.spec.ts` (if present; use the registered lifecycle spec named in validation-plan.json). They preserve the accepted URL/load/retry/lifetime assertions under the new factory guard. Extend the image-source fixture only for a malformed current upload result: return `{src:'/image-policy-pixel.png',assetId:{unexpected:true},assetVersionId:'v1'}` on the first attempt, then the existing valid result. The native expectation is zero new document images and unchanged saved JSON after attempt one, the exact metadata error, retained filename/description, then one inserted decoded image with the original description and valid IDs after retry. Host URLs remain unreleased. This new fixture/spec variant is a requested follow-up, not an executed result in this report; the same flow has executed jsdom evidence in the proposed integrated unit test.
