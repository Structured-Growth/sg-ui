## Editor installation boundary: W03-E08-DESIGN

The single package exposes `/components/PageRichTextEditorSection` and other granular controls. Existing packed fixture checks inspect resolved production module IDs: basic granular imports avoid Lexical, while editor fixtures positively require it. This is a code-loading boundary. The manifest still lists lexical and all @lexical packages as direct dependencies, so core consumers install the editor graph.

The owner decision must compare (1) a separate editor package/dependency boundary and (2) retaining the current single-package install with an explicit cost justification, including core/editor packed dependency bytes, API/export migration, shared versioning/peer compatibility and SSR/client behavior. This wave inspected existing metadata/scripts and package acceptance documentation; it ran no install, measurement build or consumer matrix and chose no new packaging policy. A documented unresolved design assessment is partial E-08, not a claim that a granular import removes install weight.
